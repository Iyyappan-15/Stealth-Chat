📄 netlify.toml
  ├── What: Configuration file Netlify reads when deploying the project.
  ├── Does: Tells Netlify which folder to publish (client/), that there is
  │         no build command needed (it's plain HTML/CSS/JS), and sets up
  │         redirect rules so page refreshes don't 404.
  └── Used by: Netlify hosting platform (automatically).

📄 .gitignore
  ├── What: A Git settings file.
  ├── Does: Tells Git which files/folders to IGNORE and never upload to GitHub.
  │         For example: node_modules/, .env files with secrets, etc.
  └── Used by: Git version control.

📄 README.md
  ├── What: The main project readme shown on GitHub.
  ├── Does: Explains what Stealth Chat is, its features, and how to run it.
  └── Used by: Developers reading the project on GitHub.

📄 DEPLOYMENT_GUIDE.md
  ├── What: A step-by-step deployment guide.
  ├── Does: Explains how to deploy the server (Render/Railway) and the
  │         client (Netlify) with screenshots and commands.
  └── Used by: You, when setting up the live app for the first time.

📄 QUICK_START.md
  ├── What: A shorter, faster version of the deployment guide.
  ├── Does: Covers only the essential steps to get the app running locally
  │         in under 5 minutes.
  └── Used by: Developers who want to run the project quickly.

📄 index.html
  ├── What: The one and only HTML page of the app (single-page app).
  ├── Does: Contains the entire visible structure of the UI:
  │           - Login screen (Create Room / Join Room)
  │           - Chat screen (header, messages, input bar)
  │           - Panic screen (decoy "work notes" page)
  │           - Security alert overlay (Protocol Breach popup)
  │         Loads all CSS and JS files in the correct order.
  └── How it fits: The browser loads this file first. Everything else
                   (CSS, JS) is linked from here.

📄 style.css
  ├── What: All the visual styling for the app.
  ├── Does: Controls colors, layout, fonts, animations, and
  │         responsive design for every screen size:
  │           - Hacker/cyber dark theme (neon green + cyan)
  │           - Glassmorphism card effects
  │           - Mobile responsive breakpoints (phones, tablets, landscape)
  │           - Message bubble styles, header layout, input bar
  │           - Animations (slide-in, blink, fadeIn)
  └── How it fits: Loaded by index.html. Makes the plain HTML look premium.

📄 config.js
  ├── What: A single-line configuration file.
  ├── Does: Sets ONE important variable:
  │           window.SIGNALING_SERVER_URL = 'https://...'
  │         This URL points to your backend WebSocket server on Render.
  │         ALL other JS files read this to know where to connect.
  └── How it fits: Must be the FIRST script loaded before webrtc.js.
                   Change this URL if you redeploy the server.

📄 crypto.js
  ├── What: Handles all encryption and decryption.
  ├── Does: Uses the browser's built-in Web Crypto API to:
  │           - Generate a public/private key pair (ECDH)
  │           - Export the public key to share with the peer
  │           - Derive a shared AES-256 session key from both keys
  │           - Encrypt outgoing messages with AES-GCM
  │           - Decrypt incoming messages with AES-GCM
  │         This is what makes messages unreadable to anyone in the middle.
  └── How it fits: main.js creates a CryptoManager instance and uses it
                   to encrypt before sending and decrypt after receiving.

📄 webrtc.js
  ├── What: Handles the real-time peer-to-peer (P2P) connection.
  ├── Does: Uses WebRTC (browser standard) to:
  │           - Connect to the signaling server via WebSocket
  │           - Exchange connection info (SDP offers/answers) with the peer
  │           - Establish a direct encrypted data channel between browsers
  │           - Send and receive raw messages over that channel
  │           - Handle peer connected/disconnected events
  │         Once connected, messages go DIRECTLY between two browsers —
  │         the server is no longer involved in the conversation.
  └── How it fits: main.js creates a WebRTCManager and passes callbacks
                   (onMessage, onConnected, onDisconnected) to it.

📄 main.js
  ├── What: The main brain/controller of the frontend app.
  ├── Does: Ties everything together:
  │           - Listens to all button clicks (Generate Room, Join, Send)
  │           - Switches between Create/Join room modes in the UI
  │           - Calls crypto.js to init keys when entering a room
  │           - Calls webrtc.js to connect to the signaling server
  │           - Displays incoming messages on screen (appendMessage)
  │           - Self-destruct countdown timer on each message
  │           - Session expiry timer (10 minutes)
  │           - Decoy mode (shows fake messages)
  │           - Panic mode (hides app, shows fake work notes)
  │           - Typing indicator logic
  └── How it fits: Loaded LAST by index.html after all other JS files,
                   because it depends on crypto.js and webrtc.js being ready.

📄 screenshotDetector.js
  ├── What: The security monitoring system.
  ├── Does: Watches for potential breaches and reacts:
  │           - PrintScreen key → triggers breach
  │           - Ctrl+P (print) → triggers breach
  │           - F12 / DevTools shortcuts → triggers breach
  │           - Window RESIZED (width change only) → triggers breach
  │             (mobile keyboard resize is ignored — height-only change)
  │           - Window blur (focus lost, NOT from mobile keyboard) → stealth lock
  │           - Copy/Cut events → blocked + breach triggered
  │           - Right-click menu → blocked
  │           - 3x ESC in 1 second → Panic Mode activated
  │           - Mouse leaves window (desktop only) → stealth lock
  │         On breach: blurs the screen, wipes messages, notifies peer.
  └── How it fits: main.js creates a ScreenshotDetector instance
                   after entering the chat room.

📄 server.js
  ├── What: The entire backend server — just one file.
  ├── Does: A Node.js + Express + WebSocket server that acts as
  │         a "signaling server" (matchmaker between two browsers):
  │           - Listens for browser connections on WebSocket
  │           - When Browser A joins room "XYZ", it waits
  │           - When Browser B joins room "XYZ", server sends "ready"
  │           - Forwards WebRTC connection messages between A and B
  │           - Locks the room once 2 people are connected (blocks 3rd)
  │           - Unlocks and cleans up room when either person leaves
  │           - Has a /health endpoint to monitor server status
  │         IMPORTANT: After the P2P connection is made, the server
  │         does NOT see any chat messages. They go directly P2P.
  └── How it fits: The backend that config.js points to.
                   webrtc.js connects to it via WebSocket (wss://)

📄 package.json
  ├── What: Node.js project configuration for the server.
  ├── Does: Lists the server's dependencies (express, ws, cors) and
  │         defines the start command ("node server.js").
  └── Used by: npm when installing/running the server.

📄 package-lock.json
  ├── What: Auto-generated by npm. DO NOT EDIT manually.
  ├── Does: Locks the exact versions of every installed package so
  │         the server works the same on every machine.
  └── Used by: npm automatically.

  HOW ALL FILES WORK TOGETHER (Flow Summary)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  User opens Netlify URL
        │
        ▼
  index.html loads → style.css (look) → config.js (server URL)
                                      → crypto.js (encryption tools)
                                      → webrtc.js (P2P connection tools)
                                      → screenshotDetector.js (security)
                                      → main.js (controller - runs last)
        │
        ▼
  User clicks "Generate Room" → main.js creates a room ID
  User clicks "Establish Link" → main.js calls webrtc.js
        │
        ▼
  webrtc.js connects to server.js (on Render) via WebSocket
  server.js matches two users in the same room
        │
        ▼
  Browsers exchange WebRTC connection info through server.js
  Direct P2P data channel is established (server no longer needed)
        │
        ▼
  main.js calls crypto.js to exchange public keys over P2P channel
  crypto.js derives shared AES-256 key (server NEVER sees this key)
        │
        ▼
  User types message → main.js → crypto.js encrypts it
                               → webrtc.js sends it directly to peer
        │
        ▼
  Peer's webrtc.js receives it → crypto.js decrypts it → main.js displays it
        │
        ▼
  screenshotDetector.js watches for security events the whole time.
  If breach detected → messages wiped, peer notified, UI locked.
